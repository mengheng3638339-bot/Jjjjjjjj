# Study Hub: fixing the 404 message

The login page is only the frontend. Login works only when `/api/login` is handled by the Study Hub backend.

## Cloudflare deployment (recommended for this project)
1. Push the contents of this folder to your GitHub repository.
2. In Cloudflare, open **Workers & Pages** and deploy the repository as a **Worker** using `wrangler.jsonc` and `worker.js` (not as a static Pages-only site).
3. Configure the D1 database binding named `DB` and R2 bucket binding named `BUCKET` to match `wrangler.jsonc`.
4. In Worker Settings > Variables and Secrets, set `INITIAL_OWNER_PASSWORD` (at least 8 characters) and `API_KEY`.
5. Deploy, then visit `https://YOUR-WORKER.workers.dev/api/health`. It should return `{"ok":true,"service":"Study Hub","mode":"cloudflare"}`.
6. Open the same Worker domain (not a separate static-only Vercel URL) and sign in with username `heng`, role `Owner`, and the password configured in `INITIAL_OWNER_PASSWORD`.

Cloudflare does not run `npm start` for this Worker deployment. Do not use `http://localhost:3000` on your phone: localhost means the phone itself.

## If the website is still deployed on Vercel
A static Vercel deployment will not automatically run `worker.js`. Use the Cloudflare Worker URL for the app, or configure a separate Vercel-compatible backend and set up API proxying. Deploying only `public/` will not provide login or data storage.

## Security
The password shown in any screenshot should be considered exposed. Change it before deployment and do not reuse it elsewhere.
